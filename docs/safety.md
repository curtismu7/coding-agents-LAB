# Safety

- Loopback bind only (`CALAB_BIND` is the explicit opt-in the container uses); the compose file publishes `127.0.0.1` only (a test pins it).
- Host header must be a loopback name; writes must be same-origin. The hook script sends no `Origin` (a script has none) and reaches only a loopback Host.
- Netguard blocks every outbound connection (fetch, socket, DNS, UDP) with a self-test, and a test asserts zero attempts in the server process across the whole API in both modes. The hook script is a separate process that test cannot observe, so the hook has its own guard, pinned by its own tests: it installs the same netguard (its attempts are reported on stderr as a LAB-NET line and asserted empty), skips any gateway that is not a loopback http(s) URL, and refuses redirects (`redirect: 'error'`, with a test where a loopback listener answers 307).
- A credential typed as your own action is never echoed: every string in the evaluate response (the call, the hook request, the hops, the reasons, the dialog) is masked, and the `/api/hook` answer, the audit entries, the gap records and the hook's stderr carry only masked or redacted text. Only the labelled scripted mock credential (`sk-MOCK-...`) is shown (rule 4). Tests assert the raw value is absent from every field for every kind of action and agent.
- The hook trims every long field to its head and tail before posting (so a big event is evaluated, never mistaken for an unreachable gateway); an event it cannot read (not JSON, over 1 MB, too complex) is no opinion when fail open, or a refusal plus exit code 2 under FailClosed.
- Mock and Live are both local. Live runs a real hook script as a child process: the agent's JSON on stdin, the native answer on stdout, a POST to this server over loopback in between. The "gateway" is this server; no tenant exists.
- **The lab never writes any managed configuration or settings file** outside its own repo or container: not in a home directory, not under `/Library` or `/etc`. The server and the hook contain no filesystem write at all, the repo scripts that write only write inside the repo, and a test pins both. The generated configuration is displayed and downloadable text only.
- The one home-directory touch is reading the optional shared settings file (`~/Development/.env`, or `STANDALONE_ENV`) with `util.parseEnv`, taking only `CODING_AGENTS_LAB_MODE`: no other key enters the server's environment. Its values are never printed or returned. A bare `MODE` in it is ignored (another app's); the lab reads `CODING_AGENTS_LAB_MODE`.
- The only credential-shaped value is one labelled mock key (`sk-MOCK-...`), assembled at run time so the repository holds no such string. Audit entries and summaries are redacted. No real credential, client secret or tenant id exists anywhere. The device certificate is a MOCK subject string; the lab never reads a certificate store.
- Input is bounded: bodies 16 KB (256 KB for a hook event, which the hook keeps under 200 KB), a custom action at most 2000 characters, a field scanned as its first and last 4000 characters, at most 5 gateways of 200 characters, workspaces and audit lists capped. Detection uses fixed prefix-anchored patterns and a linear tokenizer: no regular expression is ever built from user input, none nests quantifiers, and there is no `eval`, `Function` or `vm`. User text is rendered as React text, with control and bidi characters shown as visible escapes. Gateway values that could break a command line (quotes, spaces, shell characters) are refused.
- Only `.example` and `.invalid` hosts appear in any shipped text (a doctor check scans the filled story in every vertical). Documentation URLs are plain text only: in the README Sources list and, for a presenter to copy, on the Agents tab (served by `GET /api/sources`, never part of the story data, never fetched).
- Every product claim is labelled "Ping release claim, UNVERIFIED on our tenant" in the banner of every tab, in presenter mode too. Field names from the console swagger of 2026-10-31 are schema only; the lab says so wherever they appear. Every per-agent shape is tagged documented (read in the vendor's docs at build time) or illustrative, UNVERIFIED.
